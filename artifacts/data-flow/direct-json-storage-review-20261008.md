## Rami misti e altre evidenze da ricostruire

- `pct/template_atti.py`: ramo PostgreSQL esplicito; senza DSN, template personalizzati e preferenze leggono/scrivono JSON. La presenza del repository SQL accanto al file non prova che lo stesso ramo governi tutti i percorsi di redazione.
- `pct/termini_processuali.py`: adapter con backend selezionabile e ramo JSON; necessario seguire il costruttore operativo prima di classificarlo come fonte attiva.
- `pct/conservazione/registro.py`: registro versamenti JSON con sostituzione atomica e pacchetti cifrati distinti. Non modificare i pacchetti né confondere il registro con un mirror.
- L'inventario include anche calendario, timer, configurazione studio, notifiche, repository giuridici, profili Lex, indici/cache ed esportazioni. Ogni chiamata conserva file, riga, funzione e istruzione; non autorizza migrazioni cieche né eliminazione dei file.
- Il pannello Database etichetta ancora globalmente come mirror i JSON quando il profilo studio è SQL. I percorsi diretti sopra dimostrano che questa etichetta globale non certifica il ruolo di ciascun modulo: distinguere e correggere mediante i repository effettivi, senza nascondere avvisi.
