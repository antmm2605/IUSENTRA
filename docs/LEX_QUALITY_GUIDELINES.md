# Lex Quality Guidelines

## Regole minime
Una risposta Lex considerata valida deve:
- avere un output non vuoto;
- evitare affermazioni assolute senza base;
- esplicitare fallback o limiti;
- privilegiare fonti e contesto verificabile;
- non fingere certezza.

## Metriche consigliate
- grounding rate
- fallback rate
- latency p50 / p95
- citation presence rate
- empty response rate

## Obiettivo pratico
Non basta che Lex 'risponda'.
Deve rispondere in modo:
- stabile
- misurabile
- difendibile
